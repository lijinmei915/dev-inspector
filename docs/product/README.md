# 产品文档索引

> 用途：作为 MRD、PRD、交互文档、数据字典和业务规则的入口索引。
> 什么时候更新：产品文档结构、数据源优先级或规则落档路径变化时。
> 不要写什么：详细需求正文、交互细节、字段清单、编码规则全文、交接流水。

本目录采用更接近产品团队的文档分层：

```txt
MRD.md
PRD.md
INTERACTION_SPEC.md
DATA_DICTIONARY.md
BUSINESS_RULES.md
```

## 文档职责

| 文档 | 回答什么问题 | 主要数据源 |
|------|--------------|------------|
| `MRD.md` | 为什么做、给谁用、解决什么场景问题 | 用户访谈、市场判断、当前产品愿景、用户确认 |
| `PRD.md` | 当前产品要做什么、功能边界和验收是什么 | `PROJECT.md`、当前 demo、已确认需求、验收用例 |
| `INTERACTION_SPEC.md` | 页面、组件、状态、反馈、异常分支怎么交互 | 当前 demo、已确认交互、`docs/design/*` |
| `DATA_DICTIONARY.md` | 产品、SKU、销货号等对象和字段是什么 | PRD、代码 schema、接口、导入模板、用户确认 |
| `BUSINESS_RULES.md` | 编码、校验、去重、状态流转、导入导出规则是什么 | PRD、后端校验、前端表单、接口、导入导出样例、用户确认 |

## 总索引

- 市场与用户判断：`MRD.md`
- 当前产品需求：`PRD.md`
- 交互与状态：`INTERACTION_SPEC.md`
- 数据对象与字段：`DATA_DICTIONARY.md`
- 业务规则与编码规则：`BUSINESS_RULES.md`
- 中长期阶段规划：`../PRODUCT_PLAN.md`
- 为什么这么定：`../DECISIONS.md`

## 落档规则

| 新信息 | 写到哪里 |
|--------|----------|
| “为什么要做、目标用户是谁、场景是什么” | `MRD.md` |
| “当前版本要做哪些功能、边界是什么、怎么验收” | `PRD.md` |
| “某个页面或面板怎么操作、状态和反馈是什么” | `INTERACTION_SPEC.md` |
| “产品、SKU、销货号、客户、订单等对象是什么” | `DATA_DICTIONARY.md` |
| “销货号怎么生成 / 校验 / 去重 / 解析” | `BUSINESS_RULES.md` |
| “字段是否必填、长度、格式、枚举、状态” | `DATA_DICTIONARY.md`；校验逻辑同步到 `BUSINESS_RULES.md` |
| “为什么决定这样做” | `../DECISIONS.md` |
| “未来可能做，但当前不做” | `../PRODUCT_PLAN.md` |
| “刚做完、下一步怎么接” | `../../HANDOFF.md` |

## 数据源原则

- 不编造数据源；没有 PRD、代码、接口、导入模板、页面行为或用户确认时，标记为“未登记 / 待确认”。
- 业务事实必须标注来源；竞品或行业经验只能作为“待确认假设”。
- 同一规则只保留一个主要来源，其他文档只做索引。
