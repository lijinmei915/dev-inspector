## Inspector 总体原则

- 组件识别成功时，默认展示组件能力和外部布局；不默认展开 DOM 级散样式。
- 普通元素或未识别对象才进入元素样式模块，包括文字、容器、布局、阴影、间距。
- 纯文字语义目标只展示文字和必要布局，不展示外观 / 容器样式；判断不能只看 tag，也要识别 `title`、`subtitle`、`text`、`desc` 等文字类 class，以及只包含少量文字子节点的文本组。
- 每个 Inspector 面板只保留一个实底主按钮：底部 `发送给AI`。
- 当前值、选中态、分段控件、tab 和展开入口使用浅底、描边、字色或标记，不使用主按钮视觉。
- 进入编辑提示：`进入编辑（Mac Option+I / Windows Alt+I）`。
- 退出编辑提示：`退出编辑（Esc / Mac Option+I / Windows Alt+I）`。
- `Option+I` / `Alt+I` 是全局切换快捷键；当焦点在 input、textarea、select 或 contenteditable 内时不触发，避免输入时误切换。
- 右下角 `编辑 / 退出` 浮动按钮必须提供 hover 提示，说明当前动作和对应快捷键。
- 选中标签采用智能避让：默认在选中框上方；顶部空间不足时翻到下方；上下都不足或可能被面板挡住时进入选中框内部角标。

## 样式面板交互

- 当前采用 `方案 F：微型工具条` 作为普通元素样式面板密度方向：保留现有编辑能力，把常用属性收敛为一行式浅底工具条，点击 `+` 或进入自定义后再展开参数。

| 模块 | 默认展示 | 自定义 / 高级 | 规则来源 |
|------|----------|---------------|----------|
| 文字 | 组件式字段组：样式、内容 | 字号、字重、颜色单项调整 | `../design/tokens.md` |
| 布局 | 位置 / 尺寸 / 对齐紧凑属性表 | X/Y/W/H 数值输入；W/H 内嵌尺寸模式；水平/垂直对齐 | `../design/component-index.md` |
| 外观 | 外观预设入口 | 背景、边框、粗细、线型、圆角 | `../design/tokens.md` |
| 阴影 | 选择器内合并状态名、预览和值说明 | X/Y/模糊/扩散/颜色 | `../design/tokens.md` |
| 间距 | 文字式字段行：内边距、外边距、元素间距 | 自定义时展开四方向或 gap 输入 | `../design/tokens.md` |

## 插件区交互

- 插件区是 Inspector 内部扩展能力，用于生成 AI 任务文本，不直接修改业务源码。
- `组件制作` 第一版只处理“把当前普通元素创建为新组件”，暂不做多变体、组件库浏览、基于当前组件生成新组件、加入已有组件或自动改源码。
- 当当前对象已识别为组件时，不展示 `创建组件` 入口；组件模式继续只处理真实变体、可编辑内容、子组件入口和外部布局。
- 普通元素样式面板底部提供次级按钮 `创建组件`，靠近 `复制样式`，不使用实底主按钮；面板内仍保持 `发送给AI` 为唯一实底主按钮。
- 当普通元素是结构容器（如 section、panel、列表行、承载多个子内容的 div）时，样式面板应在常规样式模块前用淡紫色轻提示展示“建议沉淀为组件”，并提供 `创建组件` 入口；不要额外显示“普通结构元素”标签。
- 结构容器默认进入摘要模式：不直接平铺所有子文本样式、外观、布局、阴影和间距配置；只展示组件化建议、子元素分组摘要（如 `标题 2 / 正文 3 / 按钮 1`）和整体样式摘要。用户点击 `管理` 才展开子元素列表，点击 `展开调整` 才展示完整样式编辑区。
- 结构容器的完整样式模块是辅助编辑，不应让用户误以为该结构只是一段普通文本；真正的可改内容由创建组件流程自动识别后进入 AI payload。
- 点击 `创建组件` 后在当前样式面板上方打开轻量抽屉，不切换到二级工作台，也不隐藏已有样式模块；抽屉用于确认组件规范，右上角关闭回到原样式面板。
- 创建组件抽屉必须展示当前元素摘要：Inspector 展示名、真实 selector、当前文案。摘要只用于定位，不让用户在这里改源码。
- 创建组件抽屉的确认字段顺序为 `容器`、`用途`、`名称`、`使用场景`。必须先确认元素所属容器，再确认它在容器里的用途，再由 `容器 + 用途`、当前元素语义和命名规范生成组件名，例如 h1 默认 `页面 / 标题` -> `page-title` / `用于页面标题展示`。`可改内容` 由系统自动识别并写入 AI 任务，不在抽屉里单独展示确认行。
- 创建组件抽屉的字段行必须复用样式面板的统一字段行组件：左侧 label、右侧输入 / 选择控件、浅灰行背景、控件高度、字段名到控件 `8px`、控件间 `6px`，都与文字、布局、阴影和间距模块一致，不单独定义一套表单视觉。
- `容器` 指当前对象服务于哪个结构，例如 `页面 / 卡片 / 菜单 / 表单 / 弹窗 / 列表 / 导航 / 操作区 / 其他`；`用途` 指它在该容器里的职责。用途不是全局无限枚举，必须跟随容器展示 4-6 个高频推荐，并保留 `其他` 兜底。
- 用途推荐按容器收敛：例如 `列表` 只展示 `功能列表 / 数据列表 / 导航列表 / 步骤列表 / 内容列表 / 其他`；`页面` 只展示 `标题 / 正文 / 说明 / 内容区块 / 操作入口 / 其他`。不要在列表用途里混入 `数值 / 状态 / 图标 / 内容容器` 这类子元素用途。
- `内容区块` 只表示当前选中对象本身负责承载和排列内容，例如 section、panel 或普通 div；列表类结构应优先归为具体列表用途，例如 `功能列表` 或 `内容列表`，不要泛化成内容容器。
- 容器和用途字段都使用标准选择控件和下拉列表；现有组件库实例不得混入这两个下拉。需要复用已有组件时，必须另设“已有同类”提示或已有组件选择入口。
- 当同一 `容器 + 用途` 下已经存在组件，抽屉必须提示已有组件，并让用户明确选择 `复用已有组件` 或 `新建同类组件`；不得静默覆盖，也不得直接生成无语义的 `page-title-2`。
- 选择 `容器` 或 `用途` 后，系统可以联动推荐 `名称`、`使用场景` 和内部 `可改内容`；如果用户已经手动改过可见字段，不强行覆盖。
- `使用场景` 默认由系统生成一句话，说明这个组件为什么存在；用户可以编辑，但不应像 PRD 一样要求用户长文填写。
- `可改内容` 必须由系统自动识别并进入 AI payload，不作为抽屉里的用户确认字段。文本类组件默认文本内容可改，例如 h1 默认 `标题文字 title`；固定封装或子组件作为只读内容写入任务，例如 `状态标签 statusBadge，只读 / 子组件`。
- UI 不展示 `可改内容` 行，也不要使用“槽位”作为主文案；发送给 AI 时可以转换成 `props / readonly parts` 等工程结构。
- 抽屉内必须展示 AI 规则预览：使用当前元素文字、外观、布局、阴影和间距作为默认样式；token 优先；暂不创建变体；创建后用新组件替换当前元素；不改业务逻辑。
- 创建组件抽屉底部只保留一个实底主按钮 `发送给AI`，不再同时展示 `取消` / `加入本次修改`。点击后先把组件规格写入本地修改篮，类型为 `组件规格`，再复用普通样式修改的 `发送给AI` 任务生成流程。
- `组件规格` 任务文本必须包含页面、选中对象、真实 selector、组件名、由 `容器 + 用途` 合成的归类、使用场景、可改内容、只读内容和规则预览，帮助 AI 在源码中创建组件并替换当前元素。
- `同样式` 不作为独立入口保留；样式复用由底部 `复制样式` 把改动写入 `本次修改内容`，再通过 `发送给AI` 统一发送。
- 同样式类需求必须复用现有修改篮链路，任务文本由已记录的对象、范围、选择器和具体改动生成，避免出现两套并行的样式同步路径。
- 插件区第一版只负责任务生成；是否扩展为独立组件制作插件、自动应用样式、批量改源码或拆独立 npm 包，需要后续验证后再决策。

## 面板密度

- 区块标题到首行内容：`6px`。
- 同一模块内上下换行内容：`8px`，例如文字输入框到文字属性栏。
- 紧凑属性栏内控件横向间距和换行后的行间距：`6px`。
- `文字`、`布局`、`阴影`、`间距` 等区块标题固定属于 section 层，左边线保持一致；标题不能因为空态或工具条样式进入浅灰属性行内部。空态添加操作放在标题行右侧。
- 字段行采用统一布局：字段名列按内容 Hug，字段名到控件为 `8px`；右侧控件横向间距 `6px`，多行换行时纵向间距 `6px`；右侧控件列使用剩余宽度并负责换行。
- 适配超出时优先保留字段名和主要触发器完整：短控件 Hug，长 token / 颜色 / 文案控件截断显示；一行放不下时在控件列内换行，不横向溢出、不压缩 section 标题、不把字段名挤到下一行。
- 微型工具条最小高度约 `44px`，内部控件高度约 `30px`，用于文字属性、阴影、间距和布局的高频调参场景。
- 不叠加双重间距：如果上一行已有 `8px` 下间距，下一行控件不再额外加 `margin-top`。
- 数值输入不展示上下步进按钮；输入框聚焦时用键盘 `ArrowUp / ArrowDown` 按 `1px` 增减，`Enter` 用于确认或失焦。下拉型控件不展示小箭头，整块控件点击即可打开选择。
- 数值输入不使用省略号截断；空间不足时优先调整容器、收缩或换行，不显示 `...`。
- 面板内 px 类数值控件显示时去掉 `px` 后缀，例如显示 `48`、`605.9`、`4`；写入 CSS、修改记录和 AI payload 时仍保留标准 CSS 单位。
- 修改记录里的间距摘要必须带单位，例如 `右2px / 下2px`；不要沿用输入控件里的无单位简写。
- 例外：文字样式里的字号触发器保留 `px` 后缀，例如 `48px`，避免与字重等裸数字混淆；布局、间距、阴影参数仍不显示 `px`。
- 带内嵌前缀的数值输入统一组件化：`X/Y/W/H`、`上/右/下/左`、`间距`、`模糊/扩散` 共用同一输入组件和键盘步进规则。
- 输入框内前缀也属于统一组件规范：单字前缀使用约 `28px` 左内距，双字前缀或 `间距` 使用约 `42px` 左内距；前缀左侧固定约 `9px`，前缀字重弱于数值一级，前缀和数值之间必须留出可读空隙，不能贴在一起。
- 每个可编辑样式区块标题右侧预留区块级重置入口；只有该区块存在本地变动时才显示。点击后只清除当前区块的 pending / 草稿记录并还原页面临时效果，不影响其它区块。
- 区块标题行需要预留重置入口高度：带右侧 action 的标题行最小高度为 `24px`，避免 reset icon 条件出现时撑高行高造成面板抖动。
- 带视觉预览的 token 选择入口统一组件化：文字色、背景色、边框色、阴影色和阴影 token 使用同一选择控件，统一预览块尺寸、透明态、token / 自定义文案和交互状态；触发器只展示「预览块 + token / 状态名」，具体 hex / rgba / shadow 值只在下拉或 tooltip 中查看。
- `自定义` 只作为来源选择中的状态：可在下拉 / 来源入口里出现，但进入自定义态后主面板不再重复常驻 `自定义` 胶囊，直接展示可编辑参数。
- 样式来源入口采用 Figma variable 式字段交互：字段所在能力行 hover / focus 时出现无边框四小块 token icon，点击后选择 token / 空值 / 自定义来源。该入口平时不常驻占位，hover / focus 时才临时让出右侧空间。
- 字段级 source icon 必须锚定在当前字段行或控件组内；如果使用绝对定位，字段行必须提供定位上下文，不能漂到面板右侧或其它区块。间距这类 flex 控件组使用 inline source icon，hover / focus 时紧贴当前输入组后方展开，间距同控件 gap。
- token 下拉必须展示 token 名、当前数值和使用场景；没有可用 token 时保留空值项，并展示 `No variables available` 空状态，不把空值当 token。
- `自定义` 不再作为每个参数组的常驻按钮；它是来源选择器里的一个状态。进入自定义后，主面板优先展示可编辑参数，减少重复文案。
- 文字区参考组件区字段结构：使用单一卡片承载 `样式` 和 `内容` 两行，`样式` 在上、`内容` 在下；左侧字段名、右侧控件上下居中，不再把输入框和样式条拆成两个松散模块。
- 文字区字段名列按内容 Hug；字段名到控件的距离等于卡片水平内边距 `8px`，`样式` / `内容` 两行控件起点保持一致。
- 文字区、外部布局和间距都使用同一类紧凑属性行：字段名列、控件列、行内 gap 和控件高度保持一致；字段名和控件之间不要出现额外留白。
- 布局区包含位置、尺寸和对齐。`X/Y/W/H` 是输入框内前缀，不单独占一列；前缀字重接近数值，颜色比数值弱一级。`X/Y` 默认带回当前元素在页面中的视觉坐标，编辑时内部换算为 `translate` 增量应用，避免把静态布局强改成 absolute；`X/Y` 在位置组内优先一行两个输入框展示，`W/H` 在尺寸组内上下两行展示，避免内嵌 `Fill / Hug / Fixed` 挤压数值区；位置列要尽量给到可读宽度，X/Y 输入框目标宽度约 `72px`，但父容器不足时必须在容器内自适应收缩或换行，不能溢出浅灰容器；`W/H` 的 `Fill / Hug / Fixed` 模式选择嵌入对应输入框右侧，不再作为独立列展示。对齐控制进入布局区，提供水平对齐和垂直对齐，作用于 `justify-content` 与 `align-items`；只在当前选中元素本身是 flex / grid 容器时展示，普通文本包装容器不展示，避免“能点但不生效”。
- `W/H` 尺寸输入的右侧模式选择必须作为内嵌文本：右侧 inset 与左侧 `W/H` 前缀到输入框边框的视觉距离一致，均约 `9px`；`Fill / Hug / Fixed` 文案按当前文字内容 Hug，不使用固定宽度，数值输入到模式文案之间的间距为 `2px`，只预留最小防遮挡空间。
- `Fill / Hug / Fixed` 内嵌模式文案不能替代数值输入区：即使当前是 `Hug` 或 `Fill`，左侧仍要保留可点击、可输入、可显示当前计算值的数值区域；用户编辑数值时可切回 fixed。
- `Fill / Hug / Fixed` 内嵌模式文案采用纯文字视觉，不加底色、不加左侧竖线；内间距固定为 `2px`，避免挤压数值区。
- 外观区承接视觉边界和装饰属性：背景、边框、圆角、阴影都属于外观；圆角不进入间距或布局。
- 外观区的自定义态必须展示字段语义，不直接裸露数值：使用 `样式 / 背景 / 边框 / 粗细 / 线条 / 圆角` 等字段名，控件复用样式面板现有选择器、颜色选择和输入组件。
- 普通元素的外观区只在存在真实视觉边界时展开：背景非透明、存在可见边框或圆角非 0 时展示外观控件；布局壳层、页面 shell 等背景透明、无可见边框、圆角为 0 的对象只显示 `外观 +`，点击后再进入外观编辑。
- 阴影区无值时只保留外层标题 `阴影` 和标题行右侧 `+` 添加入口，标题与其它 section 左对齐，不再放入浅灰属性行内部，也不显示内部 `样式` 字段。点击后进入可编辑设置态，并初始化为自定义零值阴影。有值时再展示浅灰字段组；自定义态的 `样式` 与 `参数` 必须放在同一个浅灰字段组内，行距使用 `6px`，不能拆成两个浅灰块。自定义参数行必须补齐左侧字段名 `参数`，字段名列按内容 Hug，字段名到控件距离为 `8px`，字段名字体样式和间距区一致。自定义阴影参数区参考间距：数值字段使用内嵌前缀，避免单独标签列造成松散布局。
- 间距区跟随文字区字段结构：三项纵向排列，字段名在左，选择器或输入组在右；字段名列按内容 Hug，字段名到控件距离为 `8px`；当值为 0 时默认直接显示自定义能力行，不展示 `无` 胶囊；token 触发器按内容 Hug，内部展示紫色 token 名和灰色数值，例如 `XXL 24`；自定义态不显示 `自定义` 胶囊，直接追加短数值控件，不显示额外数值摘要；同一能力行内控件 gap 为 `6px`，方向输入宽度按 `前缀 + 当前值` Hug 计算，右侧内边距固定约 `9px`，内边距和外边距自定义态应优先保持一行排布；`上/右/下/左/间距` 是输入框内前缀，不单独占一列。
- 间距区三条浅灰能力行采用独立密度规则：能力行之间垂直间距为 `4px`，能力行内部上下 padding 为 `4px`，控件高度约 `28px`；换行只发生在右侧控件列内，换行后的控件行距仍为 `6px`，不得在控件下方额外堆出空白。
- 文字样式行中，字号、字重这类短触发器按内容 Hug；颜色这类可能较长的 token 触发器占剩余空间并允许截断。文字进入自定义态后不显示 `自定义` 胶囊，来源切换使用字段 hover token icon。

## Token / 自定义规则

- token / 自定义采用双态：命中 token 时主面板只展示 token 触发器，不在触发器外侧重复展示具体数值；具体字号、字重、颜色等参数放在下拉项或详情里。
- token 触发器按内容 Hug 自适应宽度；`任务标题`、`卡片正文` 这类短 label 不被拉伸。
- 紫色只表达 token 命中和组件语义命中。
- `自定义`、硬编码值、未命中 token 的值使用深色文字。
- `无`、`0`、`none` 属于空值状态，不算 token。
- 透明色显示为空色值：文案用 `无` 或 `透明`，色块用棋盘格 / 斜线，不用纯白色块。
- 阴影为空时只显示标题行和右侧 `+` 添加入口，不展示 `无` 下拉、预览方块或 `none`；点击 `+` 打开阴影 token / 自定义选择。
- 阴影采用统一视觉 token 选择器：状态名和预览方块在同一个选择器里展示，避免 `自定义 / token 名` 在左右两侧重复出现；具体 shadow 值和用途进入下拉或 tooltip。
- 自定义阴影的顶部能力行直接展示颜色控件；不再额外展示 `自定义` 胶囊或 X/Y/模糊/扩散摘要，下方参数区只保留 X/Y/模糊/扩散四个数值输入。
- 自定义阴影从零值开始，不继承当前 token；写入修改记录和 AI 任务时必须带具体参数值。
- 间距三类都为 0 时也直接展示内边距、外边距和元素间距三行自定义能力行；默认数值全为 0，不再显示标题行右侧 `+` 添加入口。
- 间距摘要只展示非 0 方向，例如 `上14`；不重复展示 `右0 / 下0 / 左0`。

## 组件模式

- 组件卡片默认只展示组件语义名、状态、展示方式和组件能力；Card 的 `默认 / 紧凑 / 浮起 / 强调` 在面板里叫 `展示`，Button 的真实类型分支才叫 `变体`。
- 组件内部内容按插槽开放：标题、说明文等可编辑内容只作用当前组件实例。
- 状态标签、图标、按钮等嵌套组件不在父组件里直接改；父组件只提供选择入口。
- 嵌套组件入口按具体类型命名，例如 `标签`；入口内容展示该对象当前的变体 / 状态名，不使用泛称 `子组件`。
- Form 这类组合组件进入组件模式；输入框、说明输入、取消按钮、提交按钮等内部对象作为可选择入口，不在父级 Form 里直接暴露外观、阴影、间距等散样式。
- 组件作为页面整体时，可以在组件卡片外调整外部布局。

## 发送给 AI

- `本次修改内容` 是跨对象的本地草稿篮，不跟随当前选中元素清空。
- 标题直接显示本次修改数量，例如 `本次修改内容 3`；不再显示 `已记录 0` 这类空状态徽标。
- 切换选中对象时，已改但未发送的文字、样式、布局等改动必须继续保留在草稿篮里。
- `本次修改内容` 只记录真实变化；`0px → 0px`、`无 → 无`、同 token 到同 token 不进入草稿。
- 每个对象记录支持删除图标；删除后需要清除该对象对应的本地草稿，并尽量同步还原页面上的临时效果。
- 每条属性记录支持重置图标；重置后清除该属性的本地草稿，并同步清除对应区块的临时修改。
- 修改记录图标语义：对象级删除使用垃圾桶；属性级移除 / 重置使用减号。
- 修改记录对象名使用最强文字 token（`--color-text-strong`），不使用紫色；紫色只留给 token 命中值和组件语义值。
- 面板内小型 icon action 统一为 `24px × 24px`，包括区块重置、添加、修改记录删除和单条属性移除；按钮与所在文字行使用垂直居中对齐。
- 输出页面、元素、范围、选择器、改动和定位提示。
- 元素字段使用 Inspector 展示名，真实 selector 单独输出。
- Inspector 展示名不能直接使用 `h1`、`p`、`div`、`span` 这类通用 tag；优先使用 `data-di-name`、`data-component`、`data-role`、`aria-label` 或语义 class，仍无法识别时映射成 `页面标题`、`正文文本`、`容器` 等可读角色名。真实 tag 只允许出现在 `选择器` 字段里。
- 任务文本应引导 AI 定位源码，而不是手改 `dist`。
