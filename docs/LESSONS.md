# 错误模式记录

> 每次犯错后立即记录。
> 格式：犯的错 / 根本原因 / 加了什么规则。
>
> 用途：记录错误复盘和新增约束。
> 什么时候更新：误删、误改、误判、测试跑偏、规则失效时。
> 不要写什么：成功经验、无错误的普通进展、重复的 changelog 内容。

---

## Token 命中态只显示裸值

- 犯的错：字号下拉命中了 `L / 16px` token，但触发器只显示 `16px`，没有展示紫色 token label。
- 根本原因：下拉项和触发器的展示规则没有统一，只在下拉列表里渲染 token label。
- 加了什么规则：任何样式控件当前值命中 token 时，触发器和下拉项都要展示 `token label + 原始值`；只有未命中 token 时才显示裸值。

## Source Icon 绝对定位漂移

- 犯的错：把字段级 source icon 改成 hover / focus 才显示时，只改了 icon 为绝对定位，但间距行没有提供定位上下文，导致 icon 漂到面板右侧其它区块附近。
- 根本原因：共享控件的定位规则没有同时覆盖文字、阴影、间距三个承载容器，只验证了文字 / 阴影。
- 加了什么规则：字段级 source icon 使用绝对定位时，必须锚定在对应字段行或控件组内；字段行必须提供定位上下文，并在 hover / focus 时只给当前行临时让位。

## 纯文字目标误展示外观

- 犯的错：选中页面标题 / 文本组时仍展示了外观区，用户看到背景、边框、圆角等容器控制。
- 根本原因：纯文字目标判断只看 `tagName`，没有覆盖文字语义 class 和只包含文字子节点的父级文本组。
- 加了什么规则：Text 模式判定必须同时覆盖文本 tag、文本语义 class 和小型纯文字组；命中 Text 模式时不展示外观 / 容器样式。

## Form 组件误判为普通容器

- 犯的错：选中 `.demo-form` 时进入普通元素样式模块，展示了外观、阴影、间距等散样式。
- 根本原因：组件识别只覆盖 Button、Card、Badge、Control、Icon，没有把 form / form-section 这类组合组件登记进 Component Capability Registry。
- 加了什么规则：具备 form 语义的组合块进入 Form 组件模式；内部输入和操作按钮作为子组件入口，父级只保留组件信息和外部布局。

## 空外观误展开

- 犯的错：选中 `.demo-shell` 这类页面布局壳层时，外观区展开了背景透明、边框无、圆角 0 等无效控件。
- 根本原因：外观区只按“普通元素”展示，没有判断当前对象是否存在真实视觉边界。
- 加了什么规则：普通元素只有在背景非透明、存在可见边框或圆角非 0 时才展开外观控件；空外观只显示 `外观 +`，由用户明确添加后再进入编辑。

## 尺寸模式遮挡数值输入

- 犯的错：把 `Fill / Hug / Fixed` 内嵌到 W/H 输入框后，mode slot 占满了数值区域，用户看不到也点不到数值输入。
- 根本原因：尺寸字段改成一行两个输入框后，每个字段变窄，但右侧模式 slot 仍按旧宽度占位，没有重新定义数值区最小空间。
- 加了什么规则：`Fill / Hug / Fixed` 只能占右侧固定小 slot；W/H 左侧数值区域必须始终可读可编辑，模式 slot 不能替代输入框。

## 组件制作状态同步引用旧变量

- 犯的错：给组件制作增加归属组件默认值时，在 `selectEl` 里引用了已经不存在的 `meta` 变量，导致 typecheck / build 报错。
- 根本原因：选中态派生变量命名调整后，没有把组件制作同步逻辑一起改成使用当前的 `selectedComponentMeta`。
- 加了什么规则：新增选中态派生逻辑时，默认值、草稿同步和 UI 渲染必须使用同一个已命名上下文变量；提交前先跑 typecheck，避免运行时才发现旧变量。
