> 用途：记录 DevInspector 当前识别到的组件 / primitive / Inspector 模块交互规则。
> 什么时候更新：新增组件类型、相同元素规则、可编辑白名单或模块交互规则变化时。
> 不要写什么：产品阶段规划、决策原因全文、一次性实现流水。

SSOT：

- 当前产品状态和阶段目标：`../../PROJECT.md`
- 产品文档和业务规则入口：`../product/README.md`
- 为什么采用某个交互决策：`../DECISIONS.md`
- token 命中、预设与自定义规则：`tokens.md`
- 本文件只写“具体组件或模块怎么交互”。

## 组件分层

| 层级 | 说明 |
|------|------|
| Primitive | 基础 UI 原语或跨组件元素，如 Button、Input、Icon |
| Component | 具备业务/语义类名的可复用组件，如 task-card、status-badge |
| Pattern | 业务组合与交互规则，如 SearchBar、DataTable、FormSection |
| Page | 页面级编排，不提前抽复用 |

## 视觉层级规则

- 每个 Inspector 面板只保留一个实底主按钮：底部 `发送给AI`。
- 当前值、选中态、分段控件、tab 和展开入口使用浅紫底、紫色文字、描边或标记，不使用实底反白。
- 紫色只表达 token / 组件语义命中；`自定义` 和硬编码值使用深色文字，不用紫色。
- `复制样式` 等工具动作都是次级动作，不使用主按钮视觉。
- 底部操作栏必须按“次级动作组 + 主动作”排布：左侧次级按钮使用同一套高度、左右内边距和横向间距；`创建组件` 的紫色语义只改变颜色，不改变按钮宽度策略。右侧主按钮 `发送给AI` 必须与次级按钮同高同排对齐，并保留面板右侧安全内边距；所有相邻按钮之间使用同一个 gap，不在按钮之间叠加额外 auto margin。操作数量变化时必须动态适配：普通元素四按钮状态下主按钮保持固定宽度；组件模式缺少 `创建组件` 时，主按钮吃掉剩余宽度，不能在按钮右侧留出一个空占位。
- 弹窗内也遵守同一规则：确认提交类按钮可使用实底主按钮，tab / 选项选中态不用实底主按钮。
- 组件卡片默认只展示组件语义名、状态、展示方式和组件能力；类型层级、相同元素计数、selector 属于调试信息，不默认展示。
- 组件语义名按“类型-对象”展示，例如源 class `.task-card` 在面板中显示为 `card-task`；真实 selector 随 `发送给AI` 自动带出，不在组件卡片里单独展示定位按钮。
- 组件识别成功后，不默认展示 `高级元素样式`；组件内部只通过 capability 白名单暴露变体、状态、内容插槽或子组件入口。
- 普通 DOM / 未识别对象才展示文字、外观、布局、阴影、间距等元素级样式模块。
- 选中标签需要智能避让浏览器边缘和 Inspector 面板：优先上方，空间不足翻到下方，仍不足时转为选中框内部角标。
- 面板密度：区块标题到首行内容为 `6px`；同模块内上下换行内容为 `8px`；紧凑属性栏内控件横向间距和换行行距为 `6px`；不要让上一行 `margin-bottom` 和下一行 `margin-top` 重复叠加。
- 样式面板区块标题属于 section 层，必须和面板内容左边线对齐；不要把 `文字`、`布局`、`阴影`、`间距` 这类标题放进浅灰属性行内部。无值空态的添加入口放在标题行右侧。
- 共享字段布局使用同一组间距：标题到首行内容 `6px`，字段名列到控件列 `8px`，同一能力行内控件横向间距 `6px`，换行后的行距 `6px`。字段名列按内容 Hug，控件列使用 `minmax(0, 1fr)` 承接剩余宽度。
- 适配规则：短触发器按内容 Hug；长 token / 颜色 / 文案控件允许占剩余空间并省略；一行放不下时控件在右侧内容列内换行，换行行距 `6px`，不得产生横向溢出，也不得把字段名挤到下一行。
- 当前普通元素样式面板采用 `方案 F：微型工具条`：文字属性、布局、阴影、间距优先压成浅底紧凑行；无值状态只保留标题和 `+`；已有 token / 自定义 / 数值输入 / live apply 能力都必须保留。
- 数值输入不展示上下步进按钮；输入框聚焦时使用键盘 `ArrowUp / ArrowDown` 按 `1px` 增减。下拉型控件不展示小箭头，整块控件点击即可打开选择。
- 数值输入不使用省略号截断；空间不足时优先调整容器、收缩或换行，不显示 `...`。
- 面板里的像素数值控件默认不展示 `px` 单位，只显示数字；输入裸数字时按 px 归一化写入 CSS，用户输入带单位的值也要继续兼容。文字样式里的字号触发器例外，保留 `px` 后缀，用来和字重等裸数字区分。
- 修改记录和发送给 AI 的内容必须恢复完整 CSS 单位；间距摘要显示为 `右2px / 下2px`，不能显示成输入控件里的 `右2 / 下2`。
- 所有带内嵌前缀的数值输入必须走统一输入组件：`X/Y/W/H`、`上/右/下/左`、`间距`、`模糊/扩散` 共用同一前缀、聚焦、键盘步进和输入归一化规则。
- 数值输入内部间距由统一组件负责：单字前缀左内距约 `28px`，双字前缀 / `间距` 左内距约 `42px`；前缀左侧约 `9px`，前缀颜色比数值弱一级，前缀与数值之间不能贴边或重叠。
- 文字、布局、阴影、间距等样式区块支持区块级重置：重置 icon 只在该区块有变动时出现，清除范围只限本区块，不影响其它区块或其它对象的草稿。
- 带右侧 action 的区块标题行必须预留 `24px` 最小高度，匹配重置 icon 尺寸，避免 icon 条件出现 / 消失时撑高标题行造成视觉抖动。
- 面板内小型 icon action 统一使用 `24px × 24px`：区块重置、添加、修改记录对象删除和单条属性移除都走同一尺寸；图标按钮与所在文字行垂直居中，不能出现文字居上、图标居中的错位。
- 所有带视觉预览的 token 入口必须走统一选择控件：文字色、背景色、边框色、阴影色 / 阴影 token 共用同一套预览块、token 文案、透明态和 hover/focus 样式，不在各模块里单独实现按钮。触发器只展示「预览块 + token / 状态名」，具体 hex / rgba / shadow 值只放在下拉或 tooltip 中。
- 颜色 token 下拉必须拆成上方色板滚动区和底部固定 footer row：色板内容滚动时，底部自定义输入区始终贴在弹层底部，不随内容滚走；外层下拉不额外叠加底部 padding，footer 自身上下 padding 一致；色块、hex 输入和透明度输入必须对齐间距区 compact 数值输入高度，使用同一高度变量、border-box 并垂直居中；色块按钮不得保留原生 button padding 或使用 scale hover 破坏同高；色板内容到 footer 的间距与 footer 底部收口保持同一节奏。
- `自定义` 只作为来源选择中的状态，不作为每个参数组的常驻按钮；需要出现时必须走统一控件，进入自定义态后主面板直接展示可编辑参数。
- 样式来源入口采用 Figma variable 式字段交互：字段所在能力行 hover / focus 时出现无边框四小块 token icon，用于选择 token / 空值 / 自定义来源，不在 section 标题旁常驻展示，也不在平时常驻占用右侧距离；hover / focus 时才临时让出空间。
- 字段级 source icon 使用绝对定位时，必须锚定在对应字段行或控件组内；字段行需要 `position: relative` 这类定位上下文，禁止让 icon 相对面板整体漂移。间距这类 flex 控件组使用 inline source icon，hover / focus 时紧贴当前输入组后方展开，间距同控件 gap。
- token 下拉必须展示 token 名、当前数值和使用场景；没有可用 token 时保留空值项，并展示 `No variables available` 空状态，不把空值当 token。
- `自定义` 是来源状态，不是必须常驻的参数控件；当用户已经处在自定义态时，优先直接展示可编辑参数，避免每个参数组都重复出现 `自定义` 胶囊。
- 文字区采用组件式字段组：单一卡片内按 `样式` / `内容` 两行组织，`样式` 在上、`内容` 在下；字段名在左、控件在右，和组件 capability 面板保持同构。
- 文字区字段名列按内容 Hug；字段名到控件的距离等于卡片水平内边距 `8px`，`样式` / `内容` 两行控件起点保持一致，不出现额外留白。
- 文字区、外部布局和间距属于同一套紧凑属性行组件：字段名列、控件列、行内间距和控件高度要保持统一；字段名与控件都要垂直居中。
- 间距区参考文字区字段结构：单列浅灰属性行，左侧为 `内边距` / `外边距` 字段名；`元素间距` 仅在当前对象本身是 flex / grid 容器且有 2 个及以上可见直接子项时展示，不从单个子项反推父级 gap。字段名列按内容 Hug，字段名到控件距离为 `8px`；右侧为 token 选择器或自定义输入组；当值为 0 时默认直接显示自定义能力行，不展示 `无` 胶囊；token 触发器按内容 Hug，内部展示紫色 token 名和灰色数值，例如 `XXL 24`；自定义时像文字自定义一样在同一能力行内追加短数值控件，不显示 `自定义` 胶囊，不另起独立参数面板，也不在外侧重复展示摘要；能力行内部控件间距统一为 `6px`，方向输入宽度按 `前缀 + 当前值` Hug 计算，右侧内边距固定约 `9px`，内边距和外边距自定义态应优先保持一行排布；`上 / 右 / 下 / 左 / 间距` 前缀内嵌在输入框左侧，视觉规则同布局区的 `X/Y/W/H`。
- 间距区浅灰能力行的密度单独定死：最多三条能力行，行与行之间 `4px`，每条能力行上下 padding `4px`，右侧控件高度约 `28px`；如果一行放不下，只允许右侧控件组内部换行，换行 gap 使用 `6px`，不能把字段名下方或控件下方留成大空白。
- 阴影区无值时只展示 section 标题 `阴影` 和标题行右侧 `+` 添加入口，标题必须与其它 section 左对齐；不再把 `阴影` 放进浅灰属性行，也不显示内部 `样式` 字段。点击后进入可编辑设置态，并初始化为自定义零值阴影。有值时再展示浅灰字段组；自定义态的 `样式` 与 `参数` 必须在同一个浅灰字段组里，行距使用 `6px`，不要拆成两个浅灰块。自定义参数行必须补齐左侧字段名 `参数`，字段名列按内容 Hug，字段名到控件距离为 `8px`，字段名字体样式和间距区一致。自定义阴影参数区参考间距：数值字段使用内嵌前缀，避免单独标签列造成松散布局。
- 文字样式行的短值触发器按内容 Hug，包括字号、字重；长 token 触发器可占剩余空间并截断。进入自定义态后不显示 `自定义` 胶囊，来源切换使用字段 hover token icon。
- 阴影采用统一视觉 token 选择器：选择器即摘要，内部展示阴影预览方块和 token / 自定义名；具体 shadow 值、用途和变量名进入下拉或 tooltip，展开参数区只负责调参，不重复展示同一摘要。
- 自定义阴影的顶部能力行直接展示颜色控件；不再额外展示 `自定义` 胶囊或 X/Y/模糊/扩散摘要，下方参数区只保留 X/Y/模糊/扩散四个数值输入。
- 空值阴影不展示 `无` 下拉；在标题右侧使用 `+` 作为添加入口，有 token 或自定义值后再展示选择器、预览和值说明。内边距 / 外边距空值不走 `+` 空态，默认直接呈现自定义能力行和 0 值输入；元素间距空值只有满足展示条件时才呈现，否则整行隐藏。
- 编辑入口 tooltip 文案保持同构：进入为 `进入编辑（Mac Option+I / Windows Alt+I）`，退出为 `退出编辑（Esc / Mac Option+I / Windows Alt+I）`；`Option+I` / `Alt+I` 不在输入控件聚焦时触发。

## 组件命名规范

组件命名分三层，不混在一起：

| 层 | 说明 | 示例 |
|----|------|------|
| Source selector | 页面真实 class / attribute，保留项目原始写法 | `.task-card`、`.ghost-button`、`[data-component="TaskCard"]` |
| Inspector display name | DevInspector 归一化后的语义名，用于面板和 AI 任务 | `card-task`、`button` |
| Component attributes | 变体、状态、展示方式、尺寸等组件属性，不进入组件名 | `variant: ghost`、`state: selected`、`display: compact`、`size: M` |

推荐源码命名：

- 业务组件使用“对象-类型”：`.task-card`、`.status-badge`、`.search-input`、`.user-avatar`。
- 通用组件变体优先作为 modifier 或属性表达：`.button--primary`、`data-variant="ghost"`。
- 已存在的历史写法也要识别：`.ghost-button`、`.primary-btn`、`.btn-secondary`。
- 状态使用 `is-*`、`has-*`、`state-*` 或 `--selected`、`--open`、`--disabled` 等状态修饰，不参与组件命名。
- 语义状态、尺寸等属性不参与组件命名，进入对应 capability；例如标签的 `默认 / 进行中 / 成功 / 警告 / 危险` 在面板中统一叫 `状态`。
- 组件卡片只展示组件定义允许的属性；Card 这类包含疏密、浮起、强调的选项在面板里叫 `展示`，Button 这类真实类型分支才叫 `变体`。
- 组件内部内容按插槽开放：标题、说明文等组件定义为可编辑的内容可以改；内容插槽默认只作用当前组件实例，不跟随 `相同元素` 批量改文案。
- 状态标签、图标、按钮等嵌套组件不在父组件里直接改；父组件只提供子组件入口，点击后选中对应子组件，再进入它自己的 capability 面板。
- 组件作为页面里的整体时，可以在组件卡片外调整外部布局，例如位置和尺寸。
- 外部布局采用紧凑属性表：`位置` 和 `尺寸` 并列排布；分组名只作为 X/W 上方的小灰字提示，不占左侧标题列；位置组内 X/Y 默认带回当前元素在页面中的视觉坐标，编辑时内部换算为 `translate` 增量应用，避免把静态布局强改成 absolute；X/Y 优先一行两个输入框展示，尺寸组内 W/H 上下两行展示，避免内嵌 `Fill / Hug / Fixed` 挤压数值区；位置列要尽量给到可读宽度，X/Y 输入框目标宽度约 `72px`，但父容器不足时必须在容器内自适应收缩或换行，不能溢出浅灰容器；`Fill / Hug / Fixed` 尺寸模式嵌入对应 W/H 输入框右侧，不再占独立列；X/Y/W/H 轴标内嵌在输入框左侧，字重跟数值接近、颜色弱一级；数值字段通过键盘上下键步进；不再使用方向键簇或两张大卡片。普通元素布局区可包含对齐控制，水平对齐映射 `justify-content`，垂直对齐映射 `align-items`；但只在选中元素本身是 flex / grid 容器时展示，普通文本包装容器不展示。
- `W/H` 内嵌尺寸模式是尺寸输入的一部分，不是覆盖层：模式文字贴右侧内边距，右侧 inset 与左侧 `W/H` 前缀距边框的视觉距离保持一致，均约 `9px`；`Fill / Hug / Fixed` 按当前文字内容 Hug，不使用固定宽度，数值输入到模式文案之间的间距为 `2px`，只预留最小防遮挡空间。
- `Fill / Hug / Fixed` 只能占用右侧自身文字宽度；左侧数值区必须始终可读可编辑，当前为 `Hug / Fill` 时也不能把整格变成模式按钮。
- `Fill / Hug / Fixed` 内嵌模式文案不加竖向分隔线，也不加胶囊底色；用纯文字 hover / focus 表达可点状态，内间距固定为 `2px`。
- 圆角属于 `外观` 模块，和背景、边框、阴影同属视觉边界 / 装饰属性；不放入布局或间距。
- 外观模块自定义态必须复用共享字段行和现有控件；背景、边框、粗细、线条、圆角等值必须带字段名展示，不得只显示 `0.7`、`实线`、`M 8` 这类无语义裸值。

Inspector 展示名规则：

| Source selector | Inspector display name | 属性 |
|-----------------|------------------------|------|
| `.task-card` | `card-task` | `type: Card` |
| `.status-badge` | `badge-status` | `type: Badge` |
| `.success-badge` | `badge` | `tone: success` |
| `.search-input` | `input-search` | `type: Control / Input` |
| `.ghost-button` | `button` | `variant: ghost` |
| `.primary-btn` | `button` | `variant: primary` |

开放识别规则：

- DevInspector 自带默认命名规则，作为插件分发时的推荐规范。
- 外部项目可以导入自己的 naming adapter，把 `TaskCard`、`c-card--task`、`data-component="Card"` 等写法映射成同一套 `type / object / variant / state / size`。
- 未识别组件先回退到真实 selector；用户确认后再沉淀成 adapter 规则。
- 普通元素的 Inspector display name 不能直接显示 `h1`、`p`、`div`、`span` 这类通用 tag；展示名优先读 `data-di-name`、`data-component`、`data-role`、`aria-label`，其次使用语义 class，最后才映射为 `页面标题`、`正文文本`、`容器` 等可读角色名。真实 tag 只保留在 source selector / AI 定位信息中。
- 新增组件能力前，先确认 display name、source selector 和 capability 是否已经分层清楚。

## 组件能力表

`Component Capability Registry` 是组件模式的单一配置入口。新增组件类型时，先登记能力，再渲染默认组件属性。

| 能力 | 说明 | 当前覆盖 |
|------|------|----------|
| `editableText` | 允许直接改组件文案，并即时作用到当前元素或相同元素 | Button、Badge |
| `textSlots` | 允许改组件内部已声明的可编辑内容，并即时作用到当前组件实例 | Card 标题、说明文 |
| `childSlots` | 展示父组件内可被继续选中的子组件入口；点击后切到子组件自己的 capability 面板 | Card 状态标签 |
| `variantKind` | 允许在组件定义好的真实类型分支之间切换；Card 在 UI 上展示为 `展示` | Button、Card |
| `statusKind` | 允许在组件语义状态之间切换 | Badge |
| `colorKind` | 允许调整 primitive 的语义颜色 | Icon |
| `sizeKind` | 允许在 S / M / L 尺寸间切换 | Button、Icon、Badge |

## 组件创建能力

组件创建不是新的样式模块，而是面向 AI 协作的任务生成层。

| 能力 | 输入 | 输出 | 当前边界 |
|------|------|------|----------|
| 组件创建 | 当前普通元素、Inspector 展示名、真实 selector、当前文案、容器 / 用途 / 名称 / 使用场景 / 可改内容草稿 | `组件规格` 修改项和 AI 任务文本 | 记录到本次修改篮，不自动创建组件文件；当前复用 `packages/dev-inspector/src/plugins/component-maker.ts` 的格式化与 prompt 逻辑 |

规则：

- 插件入口必须是次级入口，不抢 `发送给AI` 的主流程层级；普通元素底部显示 `创建组件`，已识别组件不显示该入口。
- `组件创建` 产品心智上独立于样式调整面板，技术上先作为 DevInspector 内置能力，不要求用户额外安装新 npm 包。
- 当前 MVP 只做“把当前普通元素创建为新组件”。暂不做组件库浏览、加入已有组件、多变体生成、基于当前组件生成新组件或自动创建源码文件。
- 页面壳层或整页容器也不使用结构摘要模式：命中 `main`、`*-shell` 或接近 app root 的页面主体时，不展示页面区块摘要、页面布局摘要或 `生成页面规格`，直接进入外观、布局、阴影、间距等普通样式模块。
- 重复集合或列表网格容器不进入组件创建：命中 `grid / list / row / stack` 这类布局容器，且一级子项存在多个同类组件或结构时，展示 `布局容器`；父层只开放位置、尺寸、padding、gap、对齐等外层布局调整，子项内容和子组件样式必须通过单独选中子项处理。
- 普通结构元素（section、panel、列表行、承载多个子内容的 div、标题说明块等）不使用结构摘要模式：不展示“建议沉淀为组件”“子元素”“整体样式”，也不展示子文本样式模块；直接进入外观、布局、阴影、间距等普通样式模块。`demo-block`、`demo-block-head` 这类普通结构块属于该类。
- 结构摘要只服务重复集合 / 列表网格容器；页面壳层、整页容器和其它符合结构容器特征的普通对象，都按普通样式模块处理。
- 点击 `创建组件` 后打开当前面板内的轻量抽屉；抽屉只收集组件规范，不切换到二级工作台，不遮断用户对当前样式面板的理解。
- 组件创建抽屉固定字段顺序：`容器`、`用途`、`名称`、`使用场景`。字段值来自当前元素的 tag、class、文字、Inspector 展示名和已有 token 判断，用户可以确认或覆盖。`可改内容` 由系统自动识别并进入 AI 任务，不在抽屉中展示确认行。
- 组件创建抽屉内的字段行必须复用样式面板共享字段行组件：label 列按内容 Hug，label 到控件 `8px`，控件间距 / 换行间距 `6px`，浅灰行背景、控件高度、输入框圆角和 hover/focus 状态与文字、布局、阴影、间距模块一致。禁止在创建组件抽屉里重新实现一套表单行样式。
- `容器` 是当前对象服务的结构，例如 `页面 / 卡片 / 菜单 / 表单 / 弹窗 / 列表 / 导航 / 操作区 / 其他`；`用途` 是它在该结构里的职责。用途必须跟随容器给有限推荐，不维护无限全局枚举；AI payload 里的 `归类` 由二者合成，例如 `页面 / 标题`、`列表 / 功能列表`。
- 用途推荐按容器收敛：`列表` 下只出现 `功能列表 / 数据列表 / 导航列表 / 步骤列表 / 内容列表 / 其他`；`页面` 下只出现 `标题 / 正文 / 说明 / 内容区块 / 操作入口 / 其他`；其它容器同理保持 4-6 个高频推荐。自定义语义通过 `其他` 和使用场景补充，不沉淀成全局枚举。
- `内容区块` 用于当前选中对象本身就是承载和排列内容的区域，例如 section、panel 或普通 div；列表类结构要优先落到具体列表用途，例如 `功能列表` 或 `内容列表`，不要泛化成内容容器。
- 组件名必须由已确认的 `容器 + 用途` 联动生成；用户手动编辑组件名后，再切换容器或用途不得强行覆盖用户输入。
- 纯文字目标默认按所属容器判断用途；h1 通常为 `页面 / 标题`，卡片内 h3 通常为 `卡片 / 标题`，p 通常为 `页面 / 正文` 或 `卡片 / 正文`。只有核心职责是承载和排列子元素时，`用途` 才是 `内容区块`；重复条目集合应优先识别为 `列表 / 功能列表`、`列表 / 数据列表` 等列表用途。
- `容器` 和 `用途` 字段必须使用标准选择控件和下拉列表；例如 h1 默认选择 `页面 + 标题`，不展示 `card-task`、`badge-status` 这类已有组件实例。
- 现有组件库实例不得混入容器或用途下拉；如果后续恢复“归属已有组件”，必须作为独立字段展示，并按兼容语义组过滤。
- 同一 `容器 + 用途` 或同一组件名已经存在时，必须显示 `已有同类` 状态，让用户明确选择 `复用已有组件` 或 `新建同类组件`。新建同类组件应优先生成带语义限定的名称，例如 `page-title-alt`、`page-title-marketing`，最后才允许数字后缀。
- 选择容器或用途后可联动推荐组件名、使用场景和内部可改内容，但不得覆盖用户已明确手改的可见字段。
- 组件名建议必须避免 `h1`、`div` 这类通用标签名；标题类元素优先生成语义名，例如 `page-title`、`section-title`、`subsection-title`；按钮、正文、容器再按语义 class 或展示名归一化。
- `使用场景` 表示这个组件为什么存在，应由系统自动生成一句短句，例如 `用于页面主标题展示`；用户只在需要时编辑，不要求像 PRD 一样长文填写。
- `可改内容` 表示新组件暴露给调用方的可编辑字段，例如标题文字、按钮文案、正文内容。它由系统自动识别，不作为抽屉里的用户确认项；文本类默认文本内容可改，固定封装或子组件以只读内容写入任务，例如 `状态标签，只读 / 子组件`。
- 不要在 UI 里叫“槽位”，也不要在创建组件抽屉里展示额外的 `可改内容` 行；发送给 AI 时可以转换成 `props / readonly parts` 等工程结构。
- 规则预览必须用自然语言说明：使用当前元素文字、外观、布局、阴影和间距作为默认样式；token 优先；暂不创建变体；创建后用新组件替换当前元素；不改业务逻辑。
- 创建组件抽屉底部只保留一个实底主按钮 `发送给AI`。点击后必须先写入 `本次修改内容`，再复用普通样式修改的 AI 任务生成流程；不能立即修改源码，也不能绕过修改篮。
- 组件创建任务必须输出真实 selector、Inspector 展示名和用户确认过的组件规范，帮助 AI 定位源码并创建/替换组件。
- `同样式` 不独立成插件；同类样式复用统一由 `复制样式` 写入 `本次修改内容`，再随 `发送给AI` 进入主流程。
- 输出必须带真实 selector 和 Inspector 展示名，帮助 AI 定位源码；仍要强调不要手改 `dist`。

## 相同元素规则

- 业务组件：按去掉状态类后的业务类名分组，例如 `.ghost-button`。
- 状态类：`is-*`、`has-*`、`state-*`、`--active`、`--selected`、`--current`、`--open`、`--disabled` 等不参与相同元素分组。
- Icon primitive：`svg.lucide` 统一按 `.lucide` 分组，不按 `lucide-search`、`lucide-file-plus` 等具体图标名拆开。
- Card：按基础类分组，例如 `.task-card`，不被 `.task-card--floating`、`.task-card--compact` 等真实变体拆开。
- Badge / Tag：按基础类分组，例如 `.status-badge`，不被 `--progress`、`--done` 等状态修饰类拆开。
- 当前元素：只作用于当前选中 DOM 元素。
- 相同元素：作用于同一组件或 primitive 分组下的元素。

## 组件交互规则

| 组件 / Primitive | 分层 | 默认模式 | 可编辑白名单 | 相同元素规则 |
|------------------|------|----------|--------------|------------|
| Button / `.ghost-button` | Component | 组件模式 | 文案、variant、尺寸 | 按按钮基础类聚合，`.ghost-button` 展示为 `button` + `variant: ghost` |
| Icon / `svg.lucide` | Primitive | 组件模式 | 尺寸、颜色；默认不暴露布局/阴影/间距 | `.lucide` |
| Badge / Tag / Chip | Component | 组件模式 | 文案、状态、尺寸 | 按基础类，如 `.status-badge` |
| Text | Primitive | 文字模块 | 文字预设、字号、字重、颜色；不默认展示容器样式 | 命中文字 tag、具体文本类或小型文本组 |
| Container | Primitive / 普通元素 | 普通元素样式模块 | 容器预设、背景、边框、圆角 | 命中具体容器类或当前元素 |
| Card | Component | 组件模式 | 展示方式；可编辑标题、说明文；状态标签作为子组件入口；外部布局独立调整 | 具体 card 类名 |
| Form / `.demo-form` | Component | 组件模式 | 表单内输入、说明输入、操作按钮作为子组件入口；外部布局独立调整 | 按具体 form 类名 |

Text 判定规则：
- 文字语义目标包括 `h1`-`h6`、`p`、`span`、`a`、`label` 等文本 tag，以及 `title`、`subtitle`、`heading`、`text`、`desc`、`copy`、`caption`、`eyebrow` 等文本语义 class。
- 如果一个普通元素只包含少量文本子节点，且不包含 button、input、svg、img、canvas 等交互 / 媒体节点，也按文本组处理。
- Text 模式不展示外观 / 容器样式；外观只给真实容器、组件或有视觉边界的普通元素使用。
- 普通 layout shell / 页面壳层如果背景透明、没有可见边框且圆角为 0，不默认展开外观控件；只保留 `外观 +`，用户明确添加外观后再展示背景、边框、圆角编辑。
