# audit

`audit` 是 project-setup 的接管项目审计 reference。

它不是独立 skill，也不是给用户复制的 prompt。它只描述当用户要接管老项目时，AI Runtime 应该如何判断现状、识别职责承接和提出收口方案。

## 适用场景

- 用户说这是已有项目、老项目、接管项目
- 当前目录已有代码或文档
- 用户想补入口、规则、结构说明或交接上下文

## 工作原则

- 不把 Runtime 目录误判成业务项目
- 不默认重做项目
- 不机械补齐所有模板文件
- 优先判断职责是否被承接，而不是文件名是否一致
- 先给现状和方案，等用户确认后再改文件

## 审计顺序

1. 确认项目状态
   - 项目类型
   - 技术栈
   - 代码和文档做到什么程度
   - 已有入口文档
   - 真实主应用入口

2. 检查职责承接
   - 总入口
   - AI 协作规则
   - 项目定义
   - 产品规划
   - 当前交接
   - 结构说明
   - 项目特殊偏好 / 上下文承接
   - 设计规范

3. 判断成熟度
   - 没有
   - 已有但较弱
   - 已有且足够
   - 已有且比 Runtime reference 更成熟

4. 给出收口方案
   - 哪些职责真的缺失
   - 哪些职责已有但建议收口
   - 哪些文档应该保留
   - 哪些文件建议新增、改名、合并或保持不动

## 输出要求

默认只输出一组问题或一类检查，不一次性铺满全部任务。

如果需要改文件，先说明方案并等待确认。改完后按“改了什么 / 为什么这样改 / 还有什么风险或待确认”汇报。
